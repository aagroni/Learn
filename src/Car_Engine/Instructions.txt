You are tasked with building a small Java application that models a fleet of vehicles using object-oriented principles. The goal is to practice encapsulation, inheritance, abstraction, polymorphism, and loose coupling in a realistic way. Start by defining an Engine interface that declares basic behaviors such as starting, stopping, returning engine type, and optionally horsepower. Then create multiple concrete implementations of this interface, such as DieselEngine, PetrolEngine, and ElectricEngine, each providing its own behavior. Next, design an abstract class called Vehicle that contains common properties like brand and model, along with an abstract method such as drive(). After that, implement a Car class that extends Vehicle and uses composition by accepting an Engine in its constructor (the constructor must take the interface type, not a concrete class). The Car class should delegate engine-related actions (like start and stop) to the provided engine instance and implement the drive() method using engine data. Additionally, create another vehicle type (e.g., Truck) that also extends Vehicle to demonstrate inheritance. To further practice loose coupling, ensure that no class depends directly on concrete engine implementations, only on the Engine interface. Add a Serviceable interface with a method like service() and make at least one vehicle implement it. In a main class, create multiple engine instances and inject them into different vehicles, store those vehicles in a collection like List<Vehicle>, and iterate over them to call drive() and other behaviors, demonstrating polymorphism. Finally, extend the system by adding a new engine type (e.g., HybridEngine) without modifying existing classes like Car, proving that your design is open for extension but closed for modification. Bonus points if you add basic validation (e.g., preventing null engines) and print meaningful output to simulate real-world behavior.
